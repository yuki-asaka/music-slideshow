# 進め方 — 仕様書・承認ゲート・レビュー

依頼者の思い出の動画なので、当方の判断で進めすぎない。段階ごとに文書を出し、承認を得てから次へ進む。
文書は `specs/` に置き、日本語で書く。指摘は小節番号でもらう。

## 目次
1. 段階と承認ゲート
2. 文書のひな形
3. レビューの回し方
4. 試写と納品

## 1. 段階と承認ゲート

| 段階 | やること | 成果物 | ゲート |
|---|---|---|---|
| 0 準備 | 素材の確認（写真の枚数・動画・曲）、写真の変換、曲の解析、キメの候補 | `data/beats.json`・`hits.json`・`work/sheets/`・`work/song_map.md` | — |
| 1 要求 | 目的・視聴者・素材・必須の内容・制約を聞き取り、要求仕様を書く | `specs/requirements.md` | **G1 要求の承認** |
| 2 設計 | 曲の構成を耳で確かめてもらい、コンセプト・シナリオ（小節単位）・演出・文字・生成画像のプロンプトを決める | `specs/design.md` | **G2 設計の承認** |
| 3 タスク | 実装の段取りと完了の条件。新しい演出やツールの使い方があれば、先に小さく検証する | `specs/task.md`（・`verification.md`） | **G3 タスクの承認** |
| 4 選定 | 写真を選び、割り付ける | `data/selection.csv`・`work/review/selection_preview_*.jpg` | G4 選定の確認 |
| 5 実装 | グラフィック → タイムライン → FilmCraft → レビュー版 | `output/review_v1.mp4` | — |
| 6 レビュー | 指摘を直して review_v2, v3… → 上映用の暫定版で試写 | `specs/review-log.md`・`output/preview_1080p.mp4` | **G5 通しと試写の承認** |
| 7 納品 | 上映用 MP4 とマスター、受け入れ基準の確認、手順の記録 | `output/*`・`specs/acceptance.md` | **G6 納品の承認** |

- 確認事項は、文書の最後に「質問」と「当方の仮定」の表で出す。依頼者が答えなかった項目は仮定のとおりに進めてよいか、承認のときに確かめる
- 2回目以降の案件（サンプル版・本番）で要求が同じなら、G1・G3 はまとめてよい（依頼者に聞く）
- 仕様を変えたら design.md の版を上げ、改訂履歴に「何を・なぜ」を書く。大きな構成の変更は `specs/change-proposal-vX.md` で先に承認を得る
- コミットするかどうか、ブランチ名は最初に聞く（「今回は不要」の案件もある）

## 2. 文書のひな形

### requirements.md
1. 目的 2. 位置づけ（試作・サンプル・本番の関係、尺、時期） 3. 視聴者 4. 入力素材（曲・写真の枚数を行事ごとに・動画・生成画像） 5. 要求（R-01…: 必ず入れる人と場面、雰囲気、文字、上映環境） 6. 非機能（N-01…: ツール、再現性、文字の大きさ、画質、音量） 7. 制約（プライバシー、外部サービス、上映の範囲） 8. 受け入れ基準 9. 確認事項と回答

受け入れ基準の例（そのまま使える）:
1. 動画の長さが曲と一致している（±1秒）
2. 切り替えの 90% 以上が拍から ±2 フレーム以内
3. すべての行事が時系列の章として登場する
4. オープニング・章タイトル・エンディングがある
5. 担任・副担任が登場する
6. レビューで指摘された「必須修正」がすべて直っている
7. 繰り返し使う演出が、次の版でも使える形でまとまっている

### design.md
1. コンセプト（物語の軸、トーン） 2. 出力仕様 3. 楽曲の分析（テンポ・最初の拍・曲の終わり・音量・時刻の基準・推定した構成の表） 4. シナリオ（4.1 全体の流れ、4.2 演出の原則、4.3 小節単位の割り付け、文字のコピー案） 5. 演出カタログ（使う演出だけ。文字の仕様、トラック構成） 6. 制作パイプライン 7. 写真の選び方 8. 生成画像（ID・用途・プロンプト） 9. レビューの方法 10. リスクと対策 11. 要求との対応 12. 確認事項
冒頭に版と改訂履歴の表を置く。

出力仕様の既定値:

| 項目 | 値 |
|---|---|
| 解像度・fps | 1920×1080・30fps |
| 上映用 | MP4（H.264 High・VBR 2パス 20Mbps・AAC 320kbps・48kHz） |
| マスター | ProRes 422・PCM（長い本編に組み込むとき用） |
| 音量 | −14 LUFS 前後（曲の実測値との差を gain_db で） |
| フェード | 頭 0.5秒、終わりは音が切れたあとの残響の最後 0.3秒だけ（曲の音を削らない） |

### task.md
段階ごとのタスク表（ID・担当（当方 / 依頼者）・内容・成果物・完了の条件）とゲート。依頼者の作業（画像の生成、耳での確認、試写）も載せる。

### review-log.md
版ごとに表で残す:

| # | 区分（必須 / できれば / 依頼） | 場所（小節） | 指摘 | 対応 | 版 |
|---|---|---|---|---|---|

### acceptance.md
納品物の表（形式・長さ・音量）と、受け入れ基準ごとの「結果・根拠」の表。

## 3. レビューの回し方

1. レビュー版は 720p・焼き込みあり（V8: タイムコード・小節.拍・区間名）。指摘を「小節45の写真」のように言ってもらえる
2. 依頼者に出す前に自己チェックする
   - `check_cuts.py` で拍とのずれ（±2 を超えたもの 0）
   - `export.py frames` で、章の頭・サビの頭・変えたところ・文字の出るところのフレームを一覧にして Read で見る（顔の見切れ、文字の重なり、白飛び）
   - 長さ（ffprobe）と音量
3. 指摘は「必須修正」と「できれば修正」に分けてもらう
4. 直すときは、原因を確かめてから直す（例: 顔が見切れる → 16:9 の切り出しの時点で切れていたので、パンチインをやめて上寄せにした）。似た箇所がほかにないかも確かめて報告する
5. デザインの好み（色・文字の見た目）は、2〜4案を並べた比較画像を作って選んでもらう。数値（コントラスト比など）も添える
6. review-log.md に記録し、design.md を直したら版を上げる

## 4. 試写と納品

- 上映用の暫定版（1080p・焼き込みなし: `apply_timeline.py --no-burnin` → `export.py video screen`）を、実際に上映するモニターで見てもらう。見るところ: 後ろの席からの文字の読みやすさ、明るさ（白フラッシュ・暗い写真）、シェイクで酔わないか、音量
- 試写で問題がなければ、上映用 MP4（試写版と同じ設定なら、そのファイルを納品名でコピーしてよい）とマスターを書き出す
- 受け入れ基準を1項目ずつ確かめて acceptance.md に書く
- プロジェクトは最後に組んだ状態（焼き込みなし）で残るので、次にレビュー版を出すときは焼き込みありで組み直す
