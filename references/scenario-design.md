# シナリオ設計 — 曲の構成と内容を重ねる

曲が替わっても写真が替わっても、考える順番は同じ。
**曲の地図を作る → 物語の軸を決める → 区間に役割を割り当てる → 小節単位で割り付ける → 演出を選ぶ。**
結果は design.md の「4. シナリオ」に表で書き、承認を得てから実装する。

## 目次
1. 曲の地図を作る
2. 物語の軸（コンセプト）を決める
3. 区間に役割を割り当てる
4. テンポの階段
5. 小節単位の割り付け
6. 文字
7. 写真の枠の配分と集合写真
8. あとから行事を足す・削るとき
9. design.md に書く表

## 1. 曲の地図を作る

1. `analyze_music.py` で拍と小節を出す（`sections` は空のまま）。テンポの残差（p95）が 40ms を超える、または inlier が 0.7 未満なら、テンポが途中で変わる曲か、`bpm_hint` が倍・半分になっている
2. `find_hits.py` でキメの候補（accent・stop・change）を出す
3. `song_map.py` で小節ごとの表（時刻・高音域・音量・キメ）を `work/song_map.md` に出す
4. 区間の境目を推定する。手がかりは次の3つ
   - 高音域の量が段で変わる小節（▲▼）。強く圧縮された J-POP は音量がほぼ平らなので、盛り上がりは高音域で見る
   - `change`（曲調の切り替わり）の候補
   - 区間は 4・8・16 小節の単位になりやすい。サビは 8 小節か 16 小節のことが多い
5. **依頼者に耳で確かめてもらう**（ここは推定で進めない）
   - 最初の拍が1拍目か（ずれていれば `downbeat_offset_beats`）
   - 区間の境目の時刻（「2:50 前後」のような答えで十分。小節に直すのは当方）
   - Bメロの頭など、迷った境目
6. `show.json` の `sections`・`chorus_bars`・`end_black_bar`・`music.last_bar` を書き、もう一度 `analyze_music.py` を実行する

時刻の基準:
- カットの時刻は `beats.json` の実測の拍だけを正とする。テンポの式で計算しない（0.1 BPM の差で、曲の終わりには 4〜5 フレームずれる）
- カットは拍の1フレーム前（`cut_offset = −1`）。人は映像の切り替えを音より少し遅れて感じるので、ちょうどより「拍に乗って」見える
- 白フラッシュの頂点とシェイクの切り替えは、拍ちょうど

## 2. 物語の軸（コンセプト）を決める

曲のタイトル・テーマと、写真の内容が重なる言葉を探して、動画全体の軸にする。
例: 曲名が「日数」を歌う曲と中学3年間（およそ1000日）→「およそ1000日の、最後の1年」。

依頼者に聞くこと（要求仕様の段階）:
- 誰が観るか（生徒・先生・保護者）、どこで観るか（教室のモニター・体育館のスクリーン）
- 何を感じてほしいか（懐かしさ・感謝・次への期待）
- 必ず入れる人・場面（担任・副担任、行事）と、入れてはいけないもの
- 文字にしてよい言葉（学校名・年度・先生の名前）
- 今回の動画のあとに続くもの（本番・続編の予告を入れるか）

歌詞を文字として画面に出すことは避ける（権利の問題があるうえ、写真が語る余地を奪う）。

## 3. 区間に役割を割り当てる

J-POP の典型的な構成と、合う内容。曲が違っても「溜めて放つ」の対応は同じ。

| 曲の区間 | 曲の性格 | 合う内容 | 写真の間隔 | 入り方 |
|---|---|---|---|---|
| イントロ〜Aメロ | 落ち着いている | オープニング（生成画像の上にコピー）→ 最初の集合写真 | 2〜4小節 | 黒から浮かぶ・ディゾルブ（長め） |
| Aメロ〜Bメロ | 少しずつ高まる | 最初の行事。Bメロは本番前の練習や準備（溜め） | 2小節 → 1小節 | ディゾルブ（長め → 短め） |
| サビ1 | 盛り上がり | いちばん動きのある行事の本番 | 1小節 → 半小節 | **白フラッシュ**から本番へ。カット。シェイク |
| 間奏〜Aメロ2〜Bメロ2 | 一度落ち着く | 余韻、静かな行事、次の大きな行事の準備 | 2小節（最後に加速） | ディゾルブ（長め） |
| サビ2 | 盛り上がり（長いことが多い） | 2つ目の大きな行事の当日、続く行事 | 1小節 → 半小節 | **シェイク**（サビ1と変化をつける）。カット |
| Cメロ | 少し落ち着く | 行事ではなく「人」: クラス、先生の紹介 | 2小節 → 1小節 | ディゾルブ（長め） |
| ラスサビ | 曲の頂点 | 笑顔のアップを次々に → グリッドの完成（動画全体の頂点） | 1小節 → 半小節 → グリッド | カット（シェイクは使わない。感情を見せる場所なので） |
| アウトロ | 静まる | 最初と同じ構図の写真 → 最新の写真（マッチディゾルブ）→ 予告・余韻のコピー → 黒 | 2小節 | グリッドの下で切り替え・ディゾルブ |

考え方:
- **時系列に進め、曲の盛り上がりと行事の盛り上がりを重ねる**。いちばん大きな行事をサビに置けるよう、静かな行事を間奏やAメロに回す
- **終盤は行事から人へ焦点を移す**。Cメロで先生と「みんな」を静かに見せ、ラスサビの最後でグリッドを完成させる
- **最後は始まりと対にする**。オープニングの集合写真と同じ構図から始め、最新の集合写真へつなぐと、時間の経過が見える
- 予告で終えると「まだ続く」余韻になる（本番や続編がある案件で特に効く）

## 4. テンポの階段

写真の間隔で、テンポの階段をはっきり作る。

- 曲全体: オープニング 2〜4小節 → Aメロ 2小節 → Bメロ 1小節 → サビ 1小節と半小節
- 区間の中でも、後半ほど短くしてサビへ加速する（静かな区間の最後の2小節を1小節ずつにし、短いディゾルブでつなぐ、など）
- 半小節が続いたあとに、1〜2小節の動画やコラージュを置いて息をつかせる
- 1小節に満たない写真（半小節 = 0.9秒）は、一目で分かる動きや表情のアップにする。集合写真や細かい写真は2小節以上

## 5. 小節単位の割り付け

区間の役割が決まったら、小節ごとに「何を・何枚・どの間隔で」を決める。

1. 区間の小節数から、写真の枠の数を出す（例: サビ 17 小節 = 1小節 × 4 ＋ 半小節 × 8 ＋ 動画 2 ＋ コラージュ 2 ＋ 半小節 × 4 ＋ …）
2. 章の頭を決める。章タイトルは章の最初の2小節
3. 強い演出（白フラッシュ・シェイク・パンチイン）は、サビの頭とキメ（`hits.json` の confirmed）に置く
4. 動画は素材の長さを見て置く（2小節 = 3.7秒の素材がなければ、1小節ずつ2本つなぐ）
5. 枠の合計と、使う写真の枚数の見込みを数える（design.md に「区間ごとの写真の枚数」として書く）

章の頭がサビの頭と重なるとき: サビの頭には文字を置かないので、章タイトルを**直前の2小節（Bメロの最後）に前倒し**し、その章の導入になる写真（入場・全景など）に重ねる。

## 6. 文字

- **文字は最小限にし、写真に語らせる**。入れるのはオープニングのコピー、章タイトル、Cメロの見出し、エンディングのコピーくらい
- **サビの頭には文字を置かない**。白フラッシュ・シェイク・強いカットで写真へ直接つなぐ
- 章タイトルは「日付（大）＋行事名（小）」。日付の書式は全章でそろえる（`04.09`・`10.21`。月しか分からない行事は `09`）
- 全文が出そろってから1小節以上（2秒以上）静止させて読ませる
- コピーの文面は必ず依頼者に確認する。学校名・年度・先生の名前の表記も確認する
- 明るい生成画像の上の文字は、白＋黒い帯よりも、背景になじむ暗い暖色の文字＋明るいにじみのほうが、デザインとして浮かず読みやすい（コントラスト比 7:1 以上を目安に、数値で確かめる）

## 7. 写真の枠の配分と集合写真

- 行事ごとの枠は、写真の枚数ではなく、物語の中の重みで決める。枚数の多い行事ほど選び抜く
- **クラス全員の集合写真は、役割のある場所だけに絞る**（オープニング、エンディングの対、先生の紹介、サビの締めの1枚など。全編で6か所程度）。同じ日の別カットを何度も使うと、繰り返しに見える
- 先生は必ず入れる。集合写真の端に写っていれば `crop` で切り出せる（2.4倍まで）。**どちらがどの先生かは依頼者に確かめる**
- 同じ顔ぶれが続かないよう、見た目で分かる範囲で散らす
- 他校・来訪者など、クラス以外の人が大きく写る写真は、上映の範囲（校内のみか）を依頼者に確かめてから使う

## 8. あとから行事を足す・削るとき

曲の長さは変えられないので、**区間の構成（サビの頭・Cメロ・ラスサビの位置）は動かさず、中身を詰め替える**。

小節を空ける方法（効く順）:
1. 集合写真の重複（同じ日の別カット）を外す
2. 長い行事を短くする（単独の写真をやめてコラージュにまとめる、など）
3. 静かな区間の中で、次の行事を前倒しで始める（章タイトルを前に出す）
4. 余韻の小節を縮める（6小節 → 2小節）

手順: まず変更案（`specs/change-proposal-vX.md`）を書き、削る写真・足す写真・小節の対応表・変わる数（章・写真・シェイク）・気になる点を示し、プレビュー画像（新しい行事の写真を色分け）を添えて承認を得る。承認後に selection.csv・show.json を直し、design.md の版を上げる。
